## 五、唯一未过线的维度：D9 = 89，以及怎么把它拿回来

D9 的 11 分缺口里，**9 分只能靠跑实验**：

| 登记行 | 最小成本 | 说明 |
| --- | --- | --- |
| **R6**（C1 单条 token） | 最低：50 条抽样，按 Agent 拆 `token_in/out` | 不需要标注集，跑完即可把 11.3 的"设计推导 15M"换成实测 |
| **R7**（P1/P2 单条 P50/P95） | 低：同 50 条，并行编排开启 | 顺带验证 8.1.1 的 4s/6s/5s 假设与 `LLM_MAX_CONCURRENT` 推导 |
| R3（Q4 JSON 解析成功率） | 低：200 条 × 6 Agent，自动化判定 | 无需人工标注 |
| R1/R2/R4（Q1/Q2/Q3/Q9） | 高：需 200 条双人标注 + 仲裁 + Kappa ≥ 0.75 | 这是 `baseline.md` 的完整协议，也是面试最可能被追问的一组 |
| R5（Q5/Q6）、R8、R9 | 依赖生产/预发环境 | 可保留 TBD 并说明"待生产数据"（11.2 填写纪律第 3 条允许） |

> 建议顺序：**R6 → R7 → R3**（三行都不需要标注，`cmd/bench` 一次跑批就能出），先把"成本与时延"从设计值变成实测值；R1/R2/R4 等标注集就绪再跑。
> 11.2 的填写纪律已经写对了（TBD 期间只能说"设计值为 X，实测待登记"），本轮所有话术也都已按此收敛——**不要在拿到数据前把它们改回完成时**。
