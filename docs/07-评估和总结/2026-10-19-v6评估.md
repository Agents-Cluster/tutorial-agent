## 二、4 处 P0（交付前必须改）

### P0-A 风险 Agent 输入契约四处打架，四路并行模型的地基是空的（本轮新暴露，最危险）

| 位置 | 口径 |
| --- | --- |
| `08:32`（加粗断言） | "风险 Agent 同样只吃 `cleaned_text`，不读 `steps_json`……代价是风险判断看不到结构化后的步骤，由质检的 `risk_suspect` 标记兜底——这是主动取舍，不是遗漏" |
| `prompts/risk.md:44-52` | Prompt 模板同时喂 `{{cleaned_text}}` **和** `{{steps_json}}`（"步骤列表（供参考）"） |
| `README.md:30` | 风险 Agent 输入 = `cleaned_text` + `steps_json` |
| `05:28` | 风险 Agent 输入 = "清洗后文本" |
| `01:116-124` / `05:35` / `08:17` | 材料/工具/步骤/风险四路**并行**，`max(四路)=6s` |

**连带矛盾**：`prompts/risk.md:9-13` 的难度判据按步骤数分档（easy ≤5 步、medium 6–12、hard >12）——如果风险真的"看不到结构化步骤"，它没有可靠来源数步骤；如果它吃 `steps_json`（按 risk.md/README 实现），依赖变成 `max(材料,工具,步骤) + 风险`，8.1.1 的 15s、11.1 的 P1/P5、6.5.1 的 33 请求秒与消费者×信号量推导全部失效——正是 08:32 自己警告的"改一处依赖，四个数字失效"，而 08:32 的断言与其自己的 Prompt 正相矛盾。

**判据**：否决项 3（同一事实两处取值不同，且是字段/机制级）；D2-6（图↔文一致）、D7-1（性能可推导）。
**改法（二选一，并全文统一）**：
- **A（推荐，保四路并行）**：`risk.md` 删除 `{{steps_json}}` 块；README:30、05:28 统一为 `cleaned_text`；难度判据不再依赖步骤数（改由"原文动作复杂度 + 工具/热源"判据，或难度档位按 `steps` 数量由**代码**在质检阶段统计回填），并在 risk.md 注明"看不到结构化步骤，步骤档位由质检兜底"。
- **B（保 prompt 现状）**：把风险改为第五串行段：清洗 → [材料|工具|步骤] → 风险 → 质检，按 08:32 的公式重算 8.1.1 / 6.5.1 / 11.1 P1-P5 / 9.2 的 `LLM_MAX_CONCURRENT` 注释，并同步 01 的 mermaid 图。

### P0-B 熔断后任务终态，10.6.5 与 06/08 仍然相反（v5 P0-2 未修）

- `06:44`、`08:67`：熔断期间任务**保持 pending**、窗口结束自动续跑；
- `10:270`（10.6.5 #3）：LLM 100% 超时 5 分钟 → "任务**进死信**；恢复后手动重试成功"。

**深层时序问题（比 v5 指出的更严重）**：6.2 的重试策略是 1s/2s/4s 指数退避、最大 3 次——100% 超时场景下，任一子任务约 7~12s 内即耗尽重试进入 DLX，而熔断窗口是 60s（`LLM_CIRCUIT_BREAK_WINDOW`）。"保持 pending 自动续跑"与重试协议在时间轴上本来就接不上：熔断在第几次失败后接管？接管前已经死信的子任务怎么办？文档没有定义这个衔接点，两个承诺同时成立不了。

**改法**：把 10.6.5 #3 改为"平台不雪崩、任务保持 pending、窗口结束后自动续跑；单条重试超限仍走 DLX"，并在 6.2 补一句熔断接管时序（例如"连续 N 次失败触发熔断后，新子任务不再进入重试协议，直接挂起等待窗口结束"）。

### P0-C 消费幂等键粒度在踩坑记录里再次倒退（v5 P0-3 未修）

- `06:25` 与 `06.2.1`：幂等键必须是 `task_no:tutorial_id:agent_name`，并专门论证"只到 task_no:tutorial_id 会让失败的 step 子任务永远修不好"；
- `10:409`（坑 4 解决方案）：`key=task_no:tutorial_id, TTL=7天`——**仍缺 `:agent_name`**，与其自己的 6.2.1 逐字矛盾。

**改法**：`10:409` 补 `:agent_name`。

### P0-D "我做了 baseline"仍以完成时态出现（v5 P0-4 残留副本）

- `10:34`：Q1 速答原文是"我做了单轮 baseline 对照（同 200 条样本、同模型、同温度）……召回率提升幅度以 11.2 的登记结果为准"；
- `11.2` R4 = **TBD**，`baseline.md` B.4 整表 **TBD**。

5.4.3 那处已改对（"方法已定稿，尚未执行"），但 10:34 仍宣称实验已执行。v5 的原话同样适用：面试官问"那组对照数据看一下"，这份文档刚说完"没测出来之前我不会说具体百分点"，二十行前就自证做过。

**改法**：`10:34` 改为"我设计了单轮 baseline 对照（协议见 baseline.md，同 200 条样本、同模型、同温度）……尚未跑，结果待登 11.2-R4"；"token 约 5 倍"改为"设计推导约 5 倍（11.3 算式），实测待 R6"。

## 五、v5 之外新发现（P2 级）

1. **Q6 与 C3 是同量双标**：11.1.3 Q6"自动入库比例 ≥ 70%"⟹ 低置信占比 ≤ 30%，而 11.1.4 C3 写"低置信占比 ≤ 20%"——同一数量（confidence<0.8 占比）两个边界，不是独立指标。非硬矛盾（C3 更严，达成 C3 即超额达成 Q6），但违反 11 自己"同一事实只出现一次"的纪律。建议 C3 注明"隐含自动入库 ≥ 80%"或与 Q6 对齐。
