# 项目文档评分标准（Rubric v1）

> 适用对象：`docs/` 下 01–11 + `baseline.md` + `prompts/`。
> 用途：给方案文档打可复现的分，并用它驱动修改——**任一维度 < 90 即视为未达交付线，必须继续优化**。
> 制定日期：2026-10-19

---

## 0.1 总分与分级

| 维度 | 权重 | 说明 |
| --- | --- | --- |
| D1 定位与叙事 | 10% | 读者 30 秒内能否说清这是什么、给谁、解决什么 |
| D2 架构与分层 | 10% | 能不能照着它开工，而不是照着它想象 |
| D3 数据设计 | 10% | 表结构能否支撑已宣称的功能 |
| D4 接口契约 | 10% | 前后端能不能不看人就能对接 |
| D5 异步与一致性 | 10% | 幂等/重试/补偿是否闭环且粒度正确 |
| D6 安全 | 10% | 认证/授权/审计/合规是否落地 |
| D7 质量属性与验收 | 10% | 指标是否可推导、可判定 |
| D8 部署可执行性 | 10% | 换一台干净机器能否跑起来 |
| D9 效果自证 | 10% | 结论有没有证据，没有证据有没有可执行的取证计划 |
| D10 文档工程 | 10% | 导航、编号、单一事实源、交叉引用 |

**综合分 = 10 个维度的算术平均**（等权，避免用权重掩盖短板）。

| 分级 | 分数 | 含义 |
| --- | --- | --- |
| A | ≥ 90 | 可交付：能直接开工 / 能直接拿去面试 |
| B | 80–89 | 需修订：有 1–3 处会被追问穿 |
| C | 70–79 | 不可用：读者会用自己的假设填补空白 |
| D | < 70 | 返工 |

**硬性否决项**（任一命中，该维度直接 ≤ 70，不论其他检查项得分）：

1. 存在指向不存在文件的引用（Prompt、配置、脚本）。
2. 存在未填占位符（`___`、`X%`、`TODO`、`待定`）且位于结论/验收/话术位置。
3. 同一事实在两处取值不同（数字、枚举、字段名、路径）。
4. 承诺了指标但全文无对应实现手段（例：RPO ≤ 1min 而无备份方案）。

| # | 检查项 | 分值 | 判据 |
| --- | --- | --- | --- |
| 1 | 一句话定位 | 20 | 含"是什么 + 给谁 + 解决什么"，不堆形容词，可复述 |
| 2 | 能力边界 | 20 | 明确写"做什么/不做什么"，且全文口径一致（不越界承诺） |

## 十一、评分流程（必须按此执行）

1. **自评**：按 D1–D10 逐项对照判据，先查硬性否决项。
2. **取证**：每个扣分项必须写"位置 + 现象 + 判据编号"，否则不计扣分。
3. **取整**：单维度保留整数，综合分取算术平均。
4. **门槛**：任一维度 < 90 → 回到修订，改完重评**全部维度**（防止此消彼长）。
5. **留痕**：每轮评分记入下表，注明改了什么。
