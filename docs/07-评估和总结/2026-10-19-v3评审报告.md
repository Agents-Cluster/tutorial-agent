## 一、本轮修的 4 个 P0

### P0-1 初始化把 `TODO` 当 Prompt（会导致 demo 第一步就挂）

`agent_configs` 的 `prompt_template` 存的是 `'TODO: 见 docs/prompts/clean.md'`，而 `clean/tool/step/risk` 四个文件根本不存在。

1. 补 4 份 Prompt（`clean.md` / `tool.md` / `step.md` / `risk.md`），与已有 2 份共 6 份，每份含"职责 + 约束 + Prompt + 输出示例 + 解析校验表"；
2. `agent_configs` 改为 `prompt_key`（`builtin:<agent>@v<N>`）+ `prompt_override`（可空），**Prompt 正文不入库**，由代码按 key 读文件；启动自检加载失败即退出；
3. 3.1 设计要点第 6 条把这个决定写清楚，避免"改文件不生效、改 SQL 才生效"的双源。

## 二、本轮新发现的 4 个问题（改稿时才发现，原评审未提）

### N-1 消费幂等键的粒度与"子任务独立重试"直接矛盾（严重）

原设计 `key = task_no:tutorial_id`。若某条教程的 `material` 成功、`step` 失败，重试 `step` 时先查标记 → **命中**（material 已写）→ 跳过 → 失败子任务永远修不好。
而文档又在 6.1 承诺"质检失败可只重试质检 Agent"。两者不可能同时成立。

已改为 `task_no:tutorial_id:agent_name`，并在 6.2.1 把这个推理写出来（这正是面试里"你这个幂等键为什么这么设计"的标准答案）。

### N-2 outbox 的 `confirmed` 状态没有回写路径

流程写"消费者 ACK 后标 confirmed"，但消息体里没有 `outbox_id`，消费者无从知道该更新哪一行。
已在 6.3 补：消息体携带 `outbox_id`，ACK 前回写；并加 `SELECT ... FOR UPDATE SKIP LOCKED` 防止多实例重复投递。

### N-3 备份脚本本身跑不通

初稿写 `docker exec diy_minio mc cp /backup/...`——`/backup` 在宿主机，minio 容器里没有这个目录，且 `local` alias 在容器重启后不保证存在。
已改为：`docker run --rm --network container:diy_minio -v $BACKUP_DIR:/backup:ro` + `MC_HOST_local` 环境变量（免 alias）。

### N-4 置信度扣分规则会算出负数

原文"每项扣 10 分 / 每对扣 8 分"没有说明基数（100 还是维度满分），也没有下限。4 个缺失字段就能吃掉全部 40% 权重，其余维度继续扣即变负。
已改为完整公式 + `clamp(0,1)` + 单测算例（0.708，与 0.8 阈值对比）。

## 四、故意不做的三件事（以及为什么）

1. **不填实测数据**：11.2 保留 9 行 TBD。文档里一个编造的"88%"会毁掉全部数字的可信度；而"TBD + 明确采集方式 + 判定人"是可验证的诚实。
2. **不写死模型单价**：改成 `12×P_in + 3×P_out` 的公式。定价会变，公式不会。
3. **不把 Prompt 正文塞进数据库**：库里只有 `prompt_key`。运营改 Prompt 走发版（可 review、可回滚），临时调参走 `prompt_override`。
