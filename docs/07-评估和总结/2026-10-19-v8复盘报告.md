| 3 | `tutorial_sets.license DEFAULT NULL`，但 5.6.2 写"必填"、4.3.7 的合规过滤靠 `license = 'self-owned'` | `NULL` 集在默认列表里**整集卡片全被隐藏**（`NULL <> 'self-owned'` 不成立但也不等于），5.6.4 的合规自检 SQL 同样漏判 | DDL 改 `NOT NULL DEFAULT 'research-only'`（最保守默认：未标注即视为评测集，不对外）；5.6.4 补上可执行的自检 SQL |

| 5 | 5.3.4 时序图第二列写 **API Gateway**，而 8.2.1/11 的 A2/10.6.5 都明确"单机无反代" | 同一事实两种说法（架构层），且 ASCII 图里"写卡片""标 confirmed"的箭头画在 outbox 列，发起方是错的 | 整块换成 **mermaid sequenceDiagram**（7 个参与者、发起方正确、含"代码算分"与"证据不含分数"两个关键点），并加一句"图中没有 Gateway/LB"的说明指向 9.12.3 |

| 7 | `expires_at` 两处语义不同：3.2 注释写"创建后 24h"，4.3.5 的响应示例却是 `null` | 票据到底从创建计时还是从生成计时，决定了"排队 20h 的导出是否还剩 4h 可用" | 统一为**文件生成后 24h**（`status=succeeded` 时写入，之前为 `NULL`）；并定义 `expired` 由 `integrity_check.sh` 回写、`archive.sh` 按月删行（9.11），把状态闭环补上 |
| 8 | 导出文件写哪个桶没写（init.sh 只建 2 个桶，示例键是 `exports/501.json`） | 实现者可能新建第三个桶，而 init.sh 不会创建它 → 导出静默失败 | 4.3.5 写明：写 `MINIO_BUCKET` 的 `exports/` 前缀，与 `uploads/` 同桶不同目录，**不新增第三个桶**；4.3.6 说明 `file_key` 是对象键不是 URL |

### 附带加固（不在 13 条内，但同批做了）

- **`/swagger/*` 生产暴露口径**：04:322 只说"CI 校验注解数"，没说这条路由在生产是否挂载、是否鉴权 → 4.7 补两条：`/swagger/*` 只在 `GIN_MODE != release` 挂载（否则等于公开完整接口面）；`/health` 与 `/metrics` 要排除在 CI 的路由数比对之外，否则数量永远对不上。

## 四、剩余问题（按可修性分类）

**A. 改文字修不了的（占剩余风险的大头）**

1. **R1–R9 全 TBD** → D9 卡在 89，这是唯一未过门槛项。最小成本路径不变：`R6`（token）→ `R7`（P50/P95）→ `R3`（JSON 解析成功率），三行都不需要标注集。
2. **真机验证**：`docker compose up -d` + `init.sh` + `health_check.sh`（现在含反代链路校验）走一遍。本轮修的 #1/#2/#11 都属于"纸上推演正确、真机才知道"的类别。
3. **前端页面级契约仍缺**：9.12 解决了"容器怎么起、请求怎么到后端"，但**页面内部**没有设计——复核页要按 `card_version` 还原 `removed_spans`、按 `quality_flags` 前缀染色、`low_confidence` 置顶，这些要求散在 5.1.5/5.2.2/5.4.4；卡片编辑页要处理 4.8.2 的部分更新语义与 `40902`。前端要开工就得补 `12-frontend.md`，否则前端会自行发明交互。

**B. 还能改文字、但收益已经很小的**

4. `GET /stats`、`/meta/enums`、`/uploads` 三个只读/工具接口没有响应示例（D4-2 的最后 4 分）；
5. `Storage`/`Publisher` 两个抽象接口没有 Go 代码级定义（D2-4）；
6. refresh token 的过期清理与并发刷新语义（D6-1）；
7. 任务状态机与 `export_tasks` 状态没有 mermaid 图（D5-6）。

> 这 4 项合计约 3–4 分，且都属于"面试不会被追问、实现时问一句就能定"的类别。**建议不再单独开一轮修它们**，等前端或后端开工时顺手补。
