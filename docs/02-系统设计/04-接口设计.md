# 04 - 接口设计

> 本文档包含：通用约定、接口清单、核心接口契约、错误码、幂等语义、导出链路、路由约定、写接口完整契约（4.8）。
> 契约以本文为准；实现与本文不一致时，改实现或改本文，不允许"代码是事实、文档是参考"。

## 4.1 通用约定

| 项 | 约定 |
| --- | --- |
| Base URL | `http://{host}:8080/api/v1`。**例外：`/health` 与 `/metrics` 挂在根路径**（`http://{host}:8080/health`），不加 `/api/v1` 前缀——Prometheus 与探活脚本按约定直连，加了前缀就要改 9.4.1 与 9.6 |
| 版本 | 路径版本 `/api/v1`，破坏性变更走 `/api/v2`，旧版保留 2 个迭代 |
| 编码 | `Content-Type: application/json; charset=utf-8`（上传除外） |
| 认证 | `Authorization: Bearer <access_token>` |
| 追踪 | 请求可带 `X-Request-Id`；未带则服务端生成；响应头回写 `X-Trace-Id` |
| 时间 | 入参出参统一 RFC3339 UTC（`2026-10-19T02:30:00Z`） |
| ID | `uint64` 数字；服务端保证 < 2^53（JS 精度安全），超过则改为字符串输出 |
| 分页 | `page`（从 1 开始，默认 1）、`page_size`（默认 20，上限 100） |
| 排序 | `sort=field,-field2`，白名单字段，非法字段返回 400 |
| 幂等 | 写接口支持 `Idempotency-Key`（UUIDv4），语义见 4.6 |

**统一响应体**（所有接口，含错误）：

```json
{ "code": 0, "message": "ok", "data": {}, "trace_id": "b7f1c2..." }
```

- `code=0` 表示成功；非 0 为业务码（见 4.5），**HTTP 状态码同时保持语义化**（400/401/403/404/409/429/500/502/503），两者不冲突：HTTP 表达传输语义，`code` 表达业务语义；
- 分页数据统一为 `{ "list": [], "total": 0, "page": 1, "page_size": 20 }`。

## 4.3 核心接口契约

### 4.3.1 `POST /tasks` 提交批量拆解任务

**请求头**：`Idempotency-Key: 7f3a...`（必填，UUIDv4）

```json
{
  "set_id": 12,
  "tutorial_ids": [1001, 1002],
  "priority": "P1",
  "agent_switches": {
    "clean": true, "material": true, "tool": true,
    "step": true, "risk": true, "quality": true
  },
  "rerun": false
}
```

| 字段 | 类型 | 必填 | 校验 | 说明 |
| --- | --- | --- | --- | --- |
| `set_id` | uint64 | 是 | 存在且未删除，有数据权限 | 教程集 |
| `tutorial_ids` | uint64[] | 否 | ≤ 500，元素属于该集 | 为空表示整集；超过 500 需拆多次提交 |
| `priority` | enum | 否 | `P0`/`P1`/`P2`，默认 `P1` | P0 仅 admin 可提 |
| `agent_switches` | object | 否 | 键为 6 个 Agent 名，`clean`/`step`/`quality` 不可关 | 关闭的 Agent 不产出字段并降置信度 |
| `rerun` | bool | 否 | — | `true` 时生成新 `card_version`，旧版 `is_current=0` |

**响应 `202 Accepted`**：

```json
{
  "code": 0,
  "message": "accepted",
  "data": {
    "task_id": 9001,
    "task_no": "T20261019-0001",
    "status": "pending",
    "total_items": 2,
    "agent_item_count": 12,
    "created_at": "2026-10-19T02:30:00Z"
  },
  "trace_id": "b7f1c2..."
}
```

**行为规格**：
1. 同一事务写 `agent_tasks`（`pending`）+ 按 `教程数 × 启用 Agent 数` 批量写 `agent_items`（`pending`）+ 写 `task_outbox`（`pending`）；
2. 接口**不等 LLM**，落库成功即返回 `202`；
3. `total_items` = 教程条数；`agent_item_count` = 子任务总数（`total_items × 启用 Agent 数`）；
4. 幂等：同 key 同 body → 返回首次结果（`200`，`data.task_id` 相同）；同 key 不同 body → `409` + `code=40901`。

**错误**：`40001` 参数非法；`40301` 无数据权限；`40901` 幂等键复用；`42901` 超出单用户并发任务上限（默认 5）。

### 4.3.2 `GET /tasks/{id}` 任务进度

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "task_id": 9001,
    "task_no": "T20261019-0001",
    "status": "running",
    "priority": "P1",
    "progress": {
      "total_items": 2,
      "success_items": 1,
      "failed_items": 0,
      "review_items": 1,
      "pending_items": 0,
      "percent": 50
    },
    "agent_breakdown": [
      { "agent_name": "clean", "succeeded": 2, "failed": 0, "running": 0, "pending": 0 },
      { "agent_name": "quality", "succeeded": 1, "failed": 0, "running": 1, "pending": 0 }
    ],
    "started_at": "2026-10-19T02:30:05Z",
    "finished_at": null,
    "error_summary": [{ "agent_name": "step", "tutorial_id": 1002, "error": "llm_timeout", "retry_count": 1 }]
  },
  "trace_id": "b7f1c2..."
}
```

- `percent` 由服务端按 **已终态子任务数 / 子任务总数** 计算，不按教程数算（一条教程 6 个 Agent，只成功 3 个时进度应为 50%，不是 100%）；
- `agent_breakdown` 是"子任务独立重试"的可视化依据：前端据此展示"第 1002 条教程的 step 失败"并可单独重试。

### 4.3.3 `POST /tasks/{id}/retry` 重试失败子任务

```json
{ "agent_names": ["step", "quality"], "tutorial_ids": [1002] }
```

| 字段 | 必填 | 校验 |
| --- | --- | --- |
| `agent_names` | 否 | 为空表示"所有 failed 子任务" |
| `tutorial_ids` | 否 | 为空表示"该任务下所有教程" |

**响应**：`200` + `{ "retried_items": 2, "task_status": "running" }`

**行为**：只把命中的 `agent_items.status` 从 `failed` 改回 `pending`、`retry_count` 保留（累计），并重新投递**子任务消息**；已完成的前序 Agent 结果直接复用，不重跑。

### 4.3.4 `PUT /cards/{id}/review` 人工复核

```json
{
  "decision": "modified",
  "reason": "步骤 3 与 4 顺序颠倒",
  "card": {
    "materials": [],
    "tools": [],
    "steps": [],
    "risks": [],
    "difficulty": { "level": "medium", "reason": "改用热熔胶" }
  }
}
```

| 字段 | 必填 | 校验 | 说明 |
| --- | --- | --- | --- |
| `decision` | 是 | `approved` / `modified` / `rejected` | 对应 `review_status`：`reviewed` / `reviewed` / `rejected` |
| `reason` | `modified`/`rejected` 时必填 | ≤ 255 字 | 写入 `review_logs.reason` |
| `card` | `modified` 时必填 | 符合 Card Schema（5.2） | 只覆盖传入的字段，未传字段保持不变 |

**行为**：同一事务写 `review_logs`（`original_json` / `modified_json` 前后快照）+ 更新 `cards`（`review_status` / `reviewed_by` / `reviewed_at`）+ 写 `operation_logs`。**复核不重算置信度**，置信度只由质检链路产出。

> `card.difficulty` 的两个子字段各有落点：`level` → `cards.difficulty`、`reason` → `cards.difficulty_reason`（3.2）。复核员改的理由必须能存下来，否则"改了、落库即丢"。
> `decision=rejected` 是**人工拒绝**的同义词；自动分流不会写 `rejected`（5.4.4）。

### 4.3.5 `POST /exports` 创建导出任务

```json
{
  "format": "json",
  "filter": {
    "set_id": 12,
    "review_status": ["auto_passed", "reviewed"],
    "confidence_min": 0.8,
    "include_eval": false,
    "created_after": "2026-10-01T00:00:00Z"
  },
  "fields": ["materials", "tools", "steps", "risks", "difficulty"]
}
```

**响应 `202`**：`{ "export_id": 501, "status": "pending", "expires_at": null }`

**约束与行为**：
1. `format` ∈ `json`/`csv`；
2. **5 万条上限在创建时同步判定**：按同一 `filter` 先跑一次 `COUNT`，超限直接返回 `40002` 且**不写 `export_tasks` 行**（不留半成品任务，前端只需提示缩小范围）；
3. 导出文件写 `MINIO_BUCKET`（`diy-tutorial-set`）的 **`exports/` 前缀**——与教程集原文件的 `uploads/` 前缀同桶不同目录，**不新增第三个桶**（init.sh 只建两个桶，见 9.3）；桶为 private，只能经签名 URL 取；
4. `expires_at` 在 `status` 变 `succeeded` 时写入（= 生成时间 + 24h），`pending`/`running` 期为 `null`；票据过期由 `integrity_check.sh` 回写 `status=expired`（9.11），`archive.sh` 按月删除过期行；
5. `filter.include_eval` 默认 `false`（口径见 4.3.7），置 `true` 需 admin；`filter_json` 原样留存以便合规回溯。

### 4.3.6 `GET /exports/{id}` 与 `GET /exports/{id}/download`

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "export_id": 501,
    "status": "succeeded",
    "row_count": 1832,
    "file_key": "exports/501.json",
    "expires_at": "2026-10-20T02:30:00Z"
  }
}
```

- 下载接口校验数据权限后返回 `302 Location: <MinIO 预签名 URL>`（有效期由 `MINIO_SIGN_EXPIRE` 控制，默认 300 秒，见 9.2），不经过应用服务中转，避免大文件占用连接；
- **签名用的 endpoint 必须是浏览器可达的地址**（`MINIO_PUBLIC_ENDPOINT`），不能直接用容器内的 `minio:9000`——否则 302 出去的 URL 宿主机解析不了，表现为"下载一直转圈然后失败"。内部读写走 `MINIO_ENDPOINT`，对外签名走 `MINIO_PUBLIC_ENDPOINT`，两个变量分离；
- `status` ∈ `pending`/`running`/`succeeded`/`failed`/`expired`（`expired` 由 `integrity_check.sh` 回写，见 9.11）；
- `file_key` 是 `MINIO_BUCKET` 内的对象键（`exports/` 前缀，4.3.5 第 3 条），不是完整 URL。

### 4.3.7 `GET /cards` 的合规过滤参数（`include_eval`）

5.6.2 要求"卡片列表与导出默认只返回 `self-owned` 集"，这条承诺必须落到接口参数上，否则前端不知道有这个开关、合规也无法验证。

| 参数 | 类型 | 默认 | 行为 |
| --- | --- | --- | --- |
| `include_eval` | bool | `false` | `false`：只返回 `tutorial_sets.license = 'self-owned'` 的卡片；`true`：额外包含评测集卡片，**仅 admin 可用** |

**行为规格**：
1. 过滤在 Repository 层用 `JOIN tutorial_sets` 实现，**不信任前端传的 `set_id`**（传了也再校验一次 license）；
2. `include_eval=true` 且当前用户非 admin → `403 / 40302`；
3. `include_eval=true` 时响应头带 `X-Eval-Only: true`，便于网关与审计区分"含评测数据的响应"；
4. 导出接口同一口径：`POST /exports` 的 `filter.include_eval` 默认为 `false`，置 `true` 同样要求 admin（4.3.5）；
5. `GET /tutorial-sets` 同理默认隐藏 `license != 'self-owned'` 的集。

> 4.5 的错误码表不需要新增码：越权走 `40302`，参数非法走 `40001`。

## 4.5 错误码

HTTP 状态码与业务码同时返回：`code` 前三位是 HTTP 状态，后两位是场景序号，便于前端按 `code` 做分支、按状态码做兜底。

| HTTP | code | 名称 | 触发场景 | 前端处理 |
| --- | --- | --- | --- | --- |
| 400 | 40001 | `INVALID_PARAM` | 参数校验失败（附 `data.fields`） | 表单定位到字段 |
| 400 | 40002 | `EXPORT_TOO_LARGE` | 导出超过 5 万条 | 提示缩小范围 |
| 401 | 40101 | `TOKEN_EXPIRED` | access token 过期 | 静默 refresh 后重放 |
| 401 | 40102 | `TOKEN_INVALID` | 签名错误 / 已登出 | 跳登录 |
| 403 | 40301 | `NO_DATA_PERMISSION` | 越权访问他人教程集 | 提示无权限 |
| 403 | 40302 | `ROLE_FORBIDDEN` | 角色不足（如 viewer 提交任务） | 隐藏入口 |
| 404 | 40401 | `NOT_FOUND` | 资源不存在或已软删 | 空态页 |
| 409 | 40901 | `IDEMPOTENCY_KEY_REUSED` | 同 key 不同 body | 生成新 key 重试 |
| 409 | 40902 | `STATE_CONFLICT` | 任务已完成仍要求重试；编辑 `archived` 卡片（需先 publish，见 5.7） | 刷新详情 |
| 429 | 42901 | `TASK_QUOTA_EXCEEDED` | 单用户并发任务 > 5 | 提示稍后 |
| 429 | 42902 | `RATE_LIMITED` | IP QPS 超限 | 退避重试 |
| 500 | 50001 | `INTERNAL_ERROR` | 未捕获异常（全局 recovery） | 展示 trace_id 便于报障 |
| 502 | 50201 | `LLM_UNAVAILABLE` | LLM 超时/熔断（同步链路不返回此码，仅健康检查与运维接口） | — |
| 503 | 50301 | `DEPENDENCY_DOWN` | MySQL/Redis/MQ 连接失败 | 提示稍后 |

> 注意：**批量任务内部的 LLM 失败不会以 502 返回给提交方**——任务提交是异步的，失败体现在 `GET /tasks/{id}` 的 `failed_items` 与 `error_summary` 里。502 只用于同步依赖 LLM 的运维接口。

## 4.6 幂等语义

| 场景 | 机制 | 重复请求的返回 |
| --- | --- | --- |
| 提交任务 / 导出 / 重试 | `Idempotency-Key` + `(user_id, idem_key)` 唯一索引 | 同 body：`200` + 首次结果；不同 body：`409 / 40901` |
| 删除、登出、复核提交 | 天然幂等（目标态一致） | 二次调用返回 `200` + 当前态 |
| MQ 重复投递 | 消费幂等标记（见 6.2） | 跳过并 ACK |

**客户端约定**（写进前端封装，避免踩坑）：
- 每次**用户主动点击**生成新 key；**网络重试**复用同一 key；
- key 用 UUIDv4，服务端保留且不复用，客户端不要用时间戳或自增 ID 当 key；
- 相同 key 的 body 必须逐字节一致（含字段顺序无关的比较由服务端按规范化 JSON 处理）。

## 4.7 路由与版本约定

1. **静态段与通配段不放在同一层**：`/cards/{id}` 与 `/cards/xxx` 这类组合一律避免，专题查询走独立前缀（`/review-queue`、`/exports`）；
2. 资源命名用复数（`/cards`、`/tasks`），动作用子路径（`/tasks/{id}/retry`）；
3. 版本只放路径第一段，`/api/v1`，不在 header 里做版本；
4. 所有接口在 `swag` 注解中标注 `@Summary/@Param/@Success/@Failure`，`/swagger/index.html` 自动生成，CI 校验注解与路由数量一致（漏注解即构建失败）；
5. **`/swagger/*` 只在 dev/test 注册**（`GIN_MODE != release` 时挂载），生产环境不挂这条路由——否则等于对外公开完整接口面与参数约束，成了攻击者的地图。生产需要查阅时，走内网端口转发或加 admin 鉴权，二者都记在 7.6；
6. `/health` 与 `/metrics` 不进 `swag` 注解统计（前者无鉴权、后者仅内网，见 7.6），CI 的路由数比对要排除这两条，否则数量永远对不上。
7. **接口与权限矩阵一一对应**：`router` 注册时必须在同一行声明所需角色，禁止在 controller 里手写角色判断（防止漏校验）。

## 4.8 补全的写接口契约

> `POST /tutorial-sets` 与 `PUT /cards/{id}` 此前在 4.4 只有字段速查，两个实现者会写出两种校验；此处补完整请求/响应/行为规格。契约以本节为准。

### 4.8.1 `POST /tutorial-sets` 创建教程集

**请求头**：`Idempotency-Key: 7f3a...`（必填，UUIDv4）

```json
{
  "name": "折纸入门精选集",
  "source_platform": "self-owned",
  "license": "self-owned",
  "version": "v1",
  "file_key": "uploads/2026/10/origami-v1.csv",
  "source_url": "https://example.com/origami"
}
```

| 字段 | 类型 | 必填 | 校验 | 说明 |
| --- | --- | --- | --- | --- |
| `name` | string | 是 | 1–128 字 | 教程集名称 |
| `source_platform` | string | 是 | ≤ 64 字（`wikihow` / `instructables` / `self-owned` / 自建平台名） | 来源平台，可溯源 |
| `license` | enum | 是 | `CC-BY-NC-SA-4.0` / `research-only` / `self-owned` | 合规锚点（5.6.2）；非法值 `40001` |
| `version` | string | 是 | ≤ 32 字，同一 `name` 下不可重复 | 重复返回 `40902` |
| `file_key` | string | 否 | 必须是 `POST /uploads` 返回过的键（`uploads/` 前缀，写入 `MINIO_BUCKET`，见 4.3.5 第 3 条） | 为空表示"直传样本"，后续由 `POST /tasks` 指定 `tutorial_ids` |
| `source_url` | string | 否 | ≤ 512 字且为合法 URL | 原始来源 |

**响应 `200`**：

```json
{
  "code": 0,
  "message": "ok",
  "data": { "set_id": 12, "sample_count": 500, "skipped_rows": [{ "line": 137, "reason": "too_short" }] },
  "trace_id": "b7f1c2..."
}
```

**行为规格**：
1. `file_key` 非空时，同一事务写 `tutorial_sets` + 解析文件批量写 `tutorials`，`sample_count` = 实际写入条数；解析失败/被准入规则拦下的行**不入库**，在 `skipped_rows` 里给出行号与原因（`too_short` / `too_long` / `empty` / `duplicate_hash` / `bad_encoding`）。`duplicate_hash` 的判定依据是 `tutorials.content_hash`（SHA-256，3.2 表 5）在**同集内**已存在——离线预处理已去重一轮（5.5.3），这里是导入期的在线兜底，两者用同一个哈希口径；
2. 准入阈值取 `DATASET_MIN_TEXT_LEN` / `DATASET_MAX_TEXT_LEN`（9.2），拦截发生在解析阶段——**不进流水线、不消耗 token**（2.2.2）；
3. 幂等：同 key 同 body → `200` + 首次结果；同 key 不同 body → `409 / 40901`（4.6）；
4. 写 `operation_logs`：`tutorial_set:import`（7.4.1）。

**错误**：`40001` 参数非法；`40302` 角色不足（viewer）；`40901` 幂等键复用；`40902` 同 `name`+`version` 已存在；`50301` MinIO 不可用（取不到 `file_key` 对应对象）。

### 4.8.2 `PUT /cards/{id}` 编辑卡片（非复核场景）

```json
{
  "materials": [{ "name": "牛皮纸", "spec": "A4 120g", "qty": 2, "unit": "张", "optional": false, "evidence": "准备两张A4牛皮纸" }],
  "tools": [{ "name": "美工刀", "required": true, "spec": "", "evidence": "用美工刀沿虚线裁切" }],
  "steps": [{ "seq": 1, "action": "沿虚线裁切纸张", "uses": ["牛皮纸", "美工刀"], "duration_est": "5min", "warnings": [] }],
  "risks": [{ "level": "medium", "type": "cut", "desc": "美工刀裁切可能割伤手指", "mitigation": "垫切割垫、戴防割手套" }],
  "difficulty": { "level": "medium", "reason": "改用热熔胶，需等待固化" }
}
```

| 字段 | 必填 | 校验 |
| --- | --- | --- |
| 五个顶层键 | 否 | **部分更新**：只覆盖传入的键，未传键保持不变 |
| 各数组元素 | 是（传了就要合法） | 必须符合 Card Schema（5.2.1）；`difficulty.level` ∈ `easy/medium/hard`；`risks[].type` ∈ `prompts/risk.md` 的风险类型枚举；`steps[].seq` 必须从 1 连续 |

**行为规格**：
1. 同一事务更新 `cards` 的 JSON 快照列与 `difficulty` / `difficulty_reason`，并**重算 `card_entities`**（按 `card_id` 删旧插新，`name_norm` 走同一张同义词表）——否则筛选会读到过期维度；
2. **不重算置信度、不改 `review_status`**：置信度只由质检链路产出（4.3.4 同口径），复核请走 `PUT /cards/{id}/review`；
3. **不产生新 `card_version`**：版本只由 `POST /tasks` 的 `rerun` 产生（4.3.1）；
4. 写 `operation_logs`：`card:update`（7.4.1），`detail` 只记变更的顶层键名列表，不记全文（5.6.3 的日志口径）；
5. 天然幂等：同一 body 重复提交结果一致。

**错误**：`40001` 参数/Schema 非法；`40301` 无数据权限；`40302` 角色不足（viewer）；`40401` 卡片不存在或已软删；`40902` 卡片为 `archived`（先 publish，见 5.7）。
