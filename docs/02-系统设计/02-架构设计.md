## 2.1 系统架构（文字版）

```
┌─────────────────────────────────────────────────────────┐
│                  前端管理后台（React）                      │
│  教程集导入 / 任务进度 / 卡片查看 / 人工复核 / 导出          │
└──────────────────────────┬──────────────────────────────┘
                           │ HTTPS / JSON
┌──────────────────────────▼──────────────────────────────┐
│                Go 后端服务（Gin）                         │
│  ┌──────────┬──────────┬──────────┬───────────────────┐  │
│  │ 路由层    │ 中间件层  │ Controller│  Service 业务层   │  │
│  │ /api/v1  │ JWT鉴权  │ 参数校验  │ 教程集/任务/卡片/   │  │
│  │          │ RBAC权限 │ 统一响应  │ 复核/导出/Agent编排 │  │
│  │          │ 限流/日志 │ 全局异常  │                   │  │
│  └──────────┴──────────┴──────────┴───────────────────┘  │
│                    │            │          │             │
│            Repository 数据层      │       Agent Client    │
│        (GORM / Redis / MinIO)    │       (LLM 封装)      │
└───────────┬───────────┬──────────┼──────────┬───────────┘
            │           │          │          │
      ┌─────▼─────┐ ┌───▼────┐ ┌───▼────┐ ┌──▼─────────┐
      │   MySQL    │ │  Redis  │ │ MinIO  │ │ RabbitMQ    │
      │ 卡片/任务  │ │ 缓存/锁 │ │ 教程文件 │ │ 任务队列     │
      └───────────┘ └────────┘ └────────┘ └──┬─────────┘
                                             │
                            ┌────────────────▼───────────────┐
                            │    多Agent流水线消费者（Worker）   │
                            │ 主规划→清洗→材料/工具/步骤/风险→质检 │
                            │ 结果落库 / 低置信进入人工复核       │
                            └────────────────────────────────┘
```

**分层架构（严格约束，面试必讲）**：

```
router（路由注册）
  → middleware（JWT / RBAC / 限流 / 日志 / 恢复）
    → controller（入参校验、统一响应、错误码转换）
      → service（业务逻辑、事务编排、任务提交、Agent 编排用例）
        → repository（数据访问：MySQL / Redis / MinIO / MQ）
```

> 铁律：Controller 不写业务逻辑、Service 不直接写 SQL、Repository 不感知 HTTP、Agent 调用统一收敛在 Agent Client 层。
>
> **依赖方向约束**：`mq/handlers` 只调 `service.ProcessTask()`，不反向 import producer；producer 通过接口注入，避免循环依赖。

## 2.2 核心模块拆解（含后端能力映射）

> 这一节是"这个平台如何 cover 全栈后端能力"的直接回答。每一项都对应一个面试考察点。

### 2.2.1 模块 1：基础 API 层（Web 服务）

- 统一请求/响应封装、错误码体系、全局异常捕获；
- 参数校验：路径、query、body 自动校验；
- 中间件体系：CORS、JWT 登录鉴权、请求日志、限流、RBAC 权限中间件；
- API 文档：Swagger 自动生成；接口版本管理：`/api/v1/...`。

### 2.2.2 模块 2：教程集管理模块

- 上传/导入：支持 TXT / MD / CSV 教程文件，存 MinIO，元数据入 MySQL；
- 教程集版本：每次导入记录版本号、来源、样本量；
- 导入准入：文件格式校验、大小限制、空文本/超长文本拦截；
- 来源元数据：数据集名称、来源平台、原始 URL/ID，可溯源。

### 2.2.3 模块 3：异步任务系统（拉开差距的核心）

- LLM 拆解是长耗时操作，HTTP 接口不能同步阻塞；
- RabbitMQ：生产者提交任务，消费者后台处理；
- 任务状态机：pending → running → succeeded / failed → dead；
- 失败重试 + 死信队列；客户端幂等键 + outbox 本地消息表；分布式锁；任务优先级。

### 2.2.4 模块 4：多 Agent 流水线模块（平台灵魂）

- Agent 编排器：按配置串行/并行调度各 Agent，传递输入输出，管理每步状态；
- Agent 协议：统一接口（输入文本/JSON → 输出 JSON），独立启停、独立重试；
- 各 Agent 职责单一：清洗、材料、工具、步骤、风险、质检；
- Agent 配置化：Prompt 模板、模型名、温度、max_tokens 落 `agent_configs` 表。

### 2.2.5 模块 5：质检与置信度模块

- **LLM 出证据，代码算分**：LLM 只输出校验证据（缺失字段、时序冲突对、原文不一致片段），程序按权重算置信度；
- 字段完整性校验：材料/工具/步骤必填项缺失即降置信度；
- 步骤时序校验：LLM 输出冲突对，程序按冲突数扣分；
- 原文一致性：实体 evidence 与原文匹配命中率；
- 置信度打分：多维度加权输出 0~1；阈值分流；复核记录回流。

### 2.2.6 模块 6：安全能力（后端必备）

- 密码 bcrypt 哈希；防 SQL 注入；XSS/CSRF 防护（token 放 header，CSRF 风险极低）；
- 敏感数据脱敏；入参过滤；MinIO 签名 URL 防盗链；
- JWT：access token 15min 无状态 + refresh token 7d 存 Redis 白名单，登出删白名单。

### 2.2.7 模块 7：可观测性（高级后端标志）

- 结构化日志：Zap 分级，日志携带 traceId，**traceId 跨 MQ 传递**（生产者写 AMQP headers，消费者读取恢复 context）；
- 监控指标：接口 QPS、错误率、耗时、任务队列堆积量、Agent 调用失败率、置信度分布、复核率、`task_e2e_duration` P50/P95/P99；**全量指标名与 labels 的唯一登记处是 9.4.1**，本节不重列（否则 `llm_tokens_total` 的 labels 会在两处写成两套）；
- Grafana 大盘可视化展示。

### 2.2.8 模块 8：测试体系（生产级开发思维）

- 单元测试：Agent 编排器、质检打分逻辑、工具函数（跟包放 `_test.go`）；
- 接口集成测试：对 HTTP 接口自动化测试；
- Agent 效果测试：固定样本集统计结构化成功率、字段召回率。

### 2.2.9 模块 9：部署与运维（全栈必备）

- Docker 镜像打包，Docker Compose 一键启动：Go、MySQL、Redis、RabbitMQ、MinIO；
- 配置分离：环境变量区分 dev/test/prod，禁止硬编码密钥；
- 优雅关闭、健康检查接口 `/health`；容器非 root 用户运行。
