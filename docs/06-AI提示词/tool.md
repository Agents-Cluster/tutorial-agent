# 工具提取 Agent Prompt

## 职责

从清洗后的教程正文中提取**工具清单**。工具 = 被反复使用、用于加工材料的器具；材料 = 会被消耗、构成成品的东西。

## 关键区分（最容易错的地方）

| 属于工具 | 属于材料 | 说明 |
| --- | --- | --- |
| 美工刀、剪刀、锯子、电钻、热熔胶枪、尺子、垫板 | 牛皮纸、白乳胶、木条、布料、热熔胶棒 | 胶水是材料，胶枪是工具；胶棒是材料 |
| 模具、夹具、砂纸（可重复使用） | 砂纸（一次性消耗完） | 按原文语境判断，判断不了标 `required=false` |

> 判断不了就**两边都提，并把"可能是材料"写进该条的 `evidence`**——输出格式没有 `note` 字段，schema 之外的字段会被解析层丢弃，宁可重复让质检去重，也不要漏。

## Prompt

```
你是手工教程的工具提取助手。请从教程文本中提取完成这个手工所需的工具。

要求：
1. 只提取原文中明确出现或明确隐含的工具（如"用电钻打孔"隐含电钻），不要脑补；
2. 每个工具包含：名称、是否必需、规格（如有）、原文依据；
3. 同一个工具的不同叫法只输出一条（美工刀/裁纸刀视为同一工具，取原文首次出现的写法）；
4. 明显属于材料而非工具的（纸张、胶水、布料），不要放进工具清单；
5. 严格输出 JSON，不要输出任何其他内容。

输出格式：
{
  "tools": [
    {
      "name": "工具名称",
      "required": true,
      "spec": "规格（没有则为空字符串）",
      "evidence": "原文中提到该工具的句子"
    }
  ]
}

教程文本：
"""
{{cleaned_text}}
"""
```

## 输出示例

```json
{
  "tools": [
    { "name": "美工刀", "required": true, "spec": "", "evidence": "用美工刀沿虚线裁切纸张" },
    { "name": "切割垫板", "required": false, "spec": "A3", "evidence": "最好垫一块切割垫板，没有的话用废纸箱也行" }
  ]
}
```

## 解析与校验

| 检查 | 处理 |
| --- | --- |
| `name` 为空或长度 > 32 | 丢弃该条，记 `parse_drop_total{agent="tool"}` |
| `tools` 为空数组 | 合法，但触发质检 `missing_fields`，按 5.4.2 扣 `completeness`（不走惩罚项） |
| `evidence` 在 `raw_text` 中找不到 | 计入 `grounding_issues`（可能编造） |
| 同卡片内 `name` 重复 | 保留首条，其余合并（取更长的 `evidence`） |

> 单条教程的工具通常 ≤ 10 个；若输出 > 20 条，多半把材料清单混进来了，解析层截断并记 `agent_anomaly_total{agent="tool",type="too_many"}`。
