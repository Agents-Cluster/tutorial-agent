## 📝 约定和术语

### 数据术语
- **卡片 (Card)**：结构化教程的单位，包含材料/工具/步骤/风险
- **教程集 (Tutorial Set)**：一组卡片的集合，共享权限、配置、成本
- **版本 (Version)**：卡片的版本号，每次重新执行管道就产生新版本

### 角色术语
- **创建者 (Creator)**：上传原始教程文本的用户
- **编辑者 (Editor)**：修改卡片内容的用户
- **审查者 (Reviewer)**：审查质量的用户
- **管理员 (Admin)**：系统管理员

### 流程术语
- **编排 (Orchestration)**：顺序执行6个Agent的流程
- **置信度 (Confidence)**：卡片质量评分（0-100）
- **质检 (Quality Check)**：质量Agent的质量评价

## 💬 FAQ

### Q1：从哪里开始？
- 新入职：先读 `01-基础面/00-项目概览.md`
- 开发者：先读 `02-系统设计/02-架构设计.md`
- 决策者：先读 [14-设计缺陷总结表](05-问题分析/14-设计缺陷总结表.md) + [16-实施路线图](04-实施指南/16-实施路线图.md)

### Q2：13个设计缺陷影响大吗？
- **影响大**：6个P1缺陷（安全、稳定、成本）必须修复
- **影响中**：5个P2缺陷（完善性）可后期修复
- **影响小**：2个P3缺陷（优化）非必须

### Q3：修复需要多长时间？
- **设计审视**：1人天
- **编码实施**：16-18人天（2-3人）
- **测试验证**：2-3人天
- **总计**：17-19人天，2-3人团队，5周

### Q4：什么时候启动？
- 有 `16-实施路线图.md` 作为完整规划
- 所有代码都已经写好，在 `15-修复方案完全指南.md` 中
- 决策者批准后，开发团队可立即启动

### Q5：如何验收？
- 每个阶段都有验收清单（在 `16-实施路线图.md` 中）
- 所有P1缺陷修复后，系统设计评分从 6/10 → 9/10
- 所有集成测试通过，端到端流程验证无误
