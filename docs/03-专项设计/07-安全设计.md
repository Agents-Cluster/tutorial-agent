# 07 - 安全设计

> 本文档包含：认证授权（JWT + RBAC）、数据安全、审计日志、传输安全、容器安全。

---

## 7.1 认证设计

### 7.1.1 JWT 双 Token 机制

| Token 类型 | 有效期 | 存储位置 | 用途 |
| --- | --- | --- | --- |
| Access Token | 15 分钟 | Header Authorization | 接口鉴权 |
| Refresh Token | 7 天 | Redis 白名单 | 刷新 Access Token |

**流程**：
1. 登录成功返回 access_token + refresh_token
2. access_token 过期后，用 refresh_token 调用 `/auth/refresh` 获取新 access_token
3. 登出时删除 Redis 中的 refresh_token 白名单

### 7.1.2 密码存储

- 使用 bcrypt 哈希存储，禁止明文存储密码；
- 密码强度要求：至少 8 位，包含字母 + 数字。

## 7.2 授权设计（RBAC）

### 7.2.1 角色定义

| 角色 | 权限 |
| --- | --- |
| admin | 全部权限 + 用户管理 + 导出 + 统计 |
| editor | 创建/上传教程集、提交拆解任务、复核卡片 |
| viewer | 只读查看卡片和教程集 |

### 7.2.2 权限矩阵

| 接口 | admin | editor | viewer |
| --- | --- | --- | --- |
| 创建教程集 | ✅ | ✅ | ❌ |
| 提交拆解任务 | ✅ | ✅ | ❌ |
| 查看卡片列表 | ✅ | ✅ | ✅ |
| 编辑卡片 | ✅ | ✅ | ❌ |
| 人工复核 | ✅ | ✅ | ❌ |
| 导出数据 | ✅ | ❌ | ❌ |
| 查看统计 | ✅ | ❌ | ❌ |
| 删除教程集 | ✅ | 本人 | ❌ |
| 发布卡片（`draft` → `published`） | ✅ | ✅（`archived` 重新上线仅 admin） | ❌ |
| 归档卡片（→ `archived`） | ✅ | ❌ | ❌ |

## 7.3 数据安全

| 措施 | 说明 |
| --- | --- |
| 软删除 | `users` 用 `status=0` 禁用 + `deleted_at`；`tutorial_sets` 删除时同事务级联置位 `tutorials` / `cards` 的 `deleted_at`，不物理删（口径见 3.4.2） |
| 数据隔离 | 教程集按 `created_by` 隔离：editor 只能看到自己创建的集及其下所有数据，admin 全量；查询在 Repository 层强制拼 `created_by = ?`，不依赖 Controller 传参 |
| 敏感信息脱敏 | 日志中不打印密码、token 等敏感字段 |
| SQL 注入防护 | GORM 参数化查询，禁止拼接 SQL |

## 7.4 审计日志

### 7.4.1 审计动作清单

以下**十个**动作必须写 `operation_logs`（`03` 的 `operation_logs.action` 注释与此处逐字对应）：
1. 导入/上传教程集 —— `tutorial_set:import`
2. 删除教程集 —— `tutorial_set:delete`
3. 重试 Agent 任务 —— `task:retry`
4. 人工复核提交 —— `card:review`
5. **直接编辑卡片**（非复核路径，4.8.2）—— `card:update`
6. **发布卡片**（`draft`/`archived` → `published`，5.7）—— `card:publish`
7. **归档卡片**（5.7）—— `card:archive`
8. 导出数据 —— `card:export`
9. 权限变更 —— `permission:change`
10. **数据下架** —— `data:takedown`（收到原作者删除请求后按 5.6.3 级联软删，属于合规动作，比"删除教程集"更需要留痕）

### 7.4.2 日志字段

| 字段 | 说明 |
| --- | --- |
| `user_id` | 操作人 ID |
| `action` | 动作类型（`资源:动作`，见 7.4.1） |
| `target_type` | 目标对象类型（`tutorial_set` / `task` / `card` / `user`） |
| `target_id` | 目标对象 ID |
| `detail` | 操作详情 JSON |
| `ip` | 操作来源 IP |
| `created_at` | 操作时间 |

> 字段名与 `operation_logs` 表（3.2）逐字段一致，避免"文档一套、建表一套"导致落库报 `Unknown column`。

## 7.5 传输安全

| 措施 | 说明 |
| --- | --- |
| HTTPS | 生产环境强制 HTTPS |
| CORS | 配置白名单，禁止 `*` |
| CSRF | token 放 Header 而非 Cookie，CSRF 风险极低 |
| Rate Limit | 登录接口限流，防暴力破解 |

## 7.6 容器与部署安全

| 措施 | 说明 |
| --- | --- |
| 非 root 运行 | 容器内使用非 root 用户运行应用 |
| 最小权限 | MySQL/Redis 密码不在代码里硬编码，走环境变量；**数据库侧同样分权**：应用连库用 `app` 账号（只有 `SELECT/INSERT/UPDATE/DELETE`），`root` 只用于 `init.sh` 建表、`backup.sh` 备份与 9.9.2 恢复演练，且不进应用容器（9.3）；`health_check.sh` 用 `app` 账号探活，不需要 root |
| 端口收敛 | 生产对外只暴露 **3001（前端静态 + 同源 `/api` 反代，见 9.12）与 9000（MinIO S3 API）**；**8080（API）不对外**，只在容器网络内被 nginx 转发。MySQL 3306、Redis 6379、RabbitMQ 5672/15672、MinIO 控制台 9001、Prometheus 9090、Grafana 3000 仅开发环境映射到宿主机，生产走内网或反代 + Basic Auth。**9000 为什么必须对外**：4.3.6 的下载与 `/uploads` 的直传都用预签名 URL，浏览器不直连 MinIO 就表现为"转圈后失败"；这里的安全由 private 桶 + 短时效签名（`MINIO_SIGN_EXPIRE`）保证，不靠端口隐藏 |
| 镜像安全 | 使用官方基础镜像，定期更新补丁版本 |

## 7.7 安全前置检查清单（上线前逐项打勾）

| # | 检查项 | 判定方法 | 不通过后果 |
| --- | --- | --- | --- |
| 1 | `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` 已改为随机 32 字节，非默认值 | `grep -c "change-me" .env` 应为 0 | token 可伪造 |
| 2 | MySQL / RabbitMQ / MinIO 默认密码已改 | 与 9.2 示例值不一致 | 容器被横向入侵 |
| 3 | `.env` 在 `.gitignore` 中，仓库历史无密钥 | `git log -S "sk-"` 无输出 | API Key 泄露，账单被打爆 |
| 4 | CORS 白名单为具体域名，无 `*` | 检查 `middleware/cors.go` | 任意站点可携带凭证调用 |
| 5 | 容器以非 root 运行 | `docker exec diy_app id -u` ≠ 0 | 容器逃逸后权限放大 |
| 6 | MinIO 两个桶（教程 `diy-tutorial-set`、备份 `diy-backup`）策略均为 private，下载只走签名 URL | `mc anonymous get local/diy-tutorial-set` 与 `local/diy-backup` 都返回 `none` | 教程原文 / 数据库备份可被公网遍历 |
| 7 | 登录接口限流生效（IP + 用户双维度） | 连打 20 次登录返回 429 | 密码暴力破解 |
| 8 | 审计十个动作全部写 `operation_logs` | 冒烟测试后查表，十类记录齐全（含 `card:update` / `card:publish` / `card:archive` / `data:takedown`） | 事后无法追责 |
| 9 | 日志不含密码/token/原文全文 | 抽样 grep 日志 | 日志成为泄露面 |
| 10 | 依赖漏洞扫描无 High/Critical | `govulncheck ./...` + `npm audit` | 已知 CVE 被打 |
| 11 | 生产环境 `SERVER_ENV=prod` 时强制 HTTPS 与安全响应头 | curl 检查 `Strict-Transport-Security` | 中间人 |
| 12 | 数据许可合规（公开集不出库） | 执行 5.6.4 的 SQL | 法务风险 |

> 这份清单是**发版门禁**：12 项全部通过才允许 `docker compose up -d`，任一项不通过只允许在 dev 环境运行。
