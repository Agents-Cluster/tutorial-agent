# 13 - 代码实现检查清单

> 本清单用于开发过程中验证代码与文档的一致性，确保没有"文档写一套、代码做一套"的情况。
> 每个模块完成后逐项 check，打钩。

---

## 13.1 Agent 流水线模块（`internal/agent/`）

### 13.1.1 编排器实现

- [ ] `orchestrator.go` 中的 `Run()` 方法：
  - [ ] 清洗 Agent 失败 → 整条教程标记失败，不执行下游四路（见 12.1.1）
  - [ ] 材料/工具/步骤/风险使用 `errgroup.WithContext` 并行执行
  - [ ] 任一并行 Agent 失败 → 记录失败但继续其他路（不 cancel context）
  - [ ] 四路完成后，汇总结果到单一 `Card` 对象（缺失字段为 `null`）
  - [ ] 质检 Agent 读取的是汇总后的卡片 + 原文，不读中间态
  
- [ ] 各 Agent 的输入严格遵循 12.1.2：
  - [ ] 材料 Agent：仅接收 `cleaned_text`
  - [ ] 工具 Agent：仅接收 `cleaned_text`
  - [ ] 步骤 Agent：仅接收 `cleaned_text`
  - [ ] **风险 Agent：仅接收 `cleaned_text`，不读 `steps_json`**（此处务必检查！）
  - [ ] 质检 Agent：接收原文 + 卡片 JSON + 移除片段

- [ ] 错误处理：
  - [ ] 清洗失败 → 返回 error，由调用方标记整条教程失败
  - [ ] 并行路失败 → 不返回 error，而是返回部分结果（缺字段）
  - [ ] 质检失败 → 返回 error，由调用方处理（标记 pending_review）

- [ ] 性能埋点：
  - [ ] 记录 T(清洗)、T(并行四路各自)、T(质检)、T(落库)
  - [ ] 埋点名称与 `internal/observability/metrics.go` 对齐

---

### 13.1.2 清洗 Agent（`clean_agent.go`）

- [ ] 输出结构必须包含：`cleaned_text` + `removed_spans[]` + `kept_ratio`
  - [ ] `removed_spans` 中每项包含：`reason` + `text`（无 `start/end`）
  - [ ] `reason` 枚举为英文：`ad` / `chat` / `meta` / `duplicate` / `broken`（与 `prompts/clean.md` 对齐）

- [ ] 后端计算偏移量（`start/end`）：
  - [ ] 对每条 `removed_spans[i].text`，在 `raw_text` 中查找唯一位置
  - [ ] 找到 → 补 `start/end`；未找到或多处 → 丢弃该 span，记指标 `span_drop_total{reason="not_found"}`
  - [ ] 验证：`raw_text[start:end] === text`（不等则不写库）

- [ ] 降级标记（见 5.1.5 两个条件，OR 关系）：
  - [ ] 条件 1：`kept_ratio < 0.5` → 标 `clean_degraded` flag
  - [ ] 条件 2：能找到偏移的 span 比例 < 50% → 标 `clean_degraded` flag
  - [ ] 触发时扣 0.10（在 `quality` 维度）

- [ ] 落库：
  - [ ] 插入或更新 `card_entities` 表吗？不，清洗不涉及实体
  - [ ] 写 `cards.removed_spans` 为 JSON 数组

---

### 13.1.3 材料提取 Agent（`material_agent.go`）

- [ ] 输出结构：`materials[]` 数组，每项包含：
  - [ ] `name`（必填）
  - [ ] `spec`（可选，如 "A4 120g"）
  - [ ] `qty`（可选，数字）
  - [ ] `unit`（可选，如 "张" / "ml"）
  - [ ] `optional`（必填，bool）
  - [ ] `evidence`（必填，原文片段）

- [ ] 落库：
  - [ ] `cards.materials_json` ← JSON 数组
  - [ ] `card_entities` 表：每个材料生成一行
    - [ ] `entity_type = "material"`
    - [ ] `name` ← 原始名称
    - [ ] `name_norm` ← 归一化后名称（同义词表）
    - [ ] `spec` ← 规格信息
    - [ ] 唯一键：`(card_id, entity_type, name_norm)`

- [ ] 置信度影响：
  - [ ] 若 `materials === null` 或 `[]` → `completeness` 扣 0.10

---

### 13.1.4 工具提取 Agent（`tool_agent.go`）

- [ ] 输出结构：`tools[]` 数组，每项包含：
  - [ ] `name`（必填）
  - [ ] `required`（必填，bool）
  - [ ] `spec`（可选）
  - [ ] `evidence`（必填）

- [ ] 落库：
  - [ ] `cards.tools_json` ← JSON 数组
  - [ ] `card_entities` 表：每个工具生成一行
    - [ ] `entity_type = "tool"`
    - [ ] `name_norm` ← 归一化后
    - [ ] 唯一键：`(card_id, entity_type, name_norm)`

- [ ] 置信度影响：
  - [ ] 若 `tools === null` 或 `[]` → `completeness` 扣 0.10

---

### 13.1.5 步骤拆解 Agent（`step_agent.go`）

- [ ] 输出结构：`steps[]` 数组，每项包含：
  - [ ] `seq`（必填，整数，从 1 开始）
  - [ ] `action`（必填，步骤描述）
  - [ ] `uses[]`（可选，材料/工具名称数组，**按原文写法**，不做归一化）
  - [ ] `duration_est`（可选，如 "5min"）
  - [ ] `warnings[]`（可选，该步骤的注意事项）

- [ ] 关键约束：
  - [ ] **`uses` 里的名称是原文写法**，后端由 scorer 与 `card_entities.name_norm` 做匹配
  - [ ] 不要求步骤 Agent 在并行阶段就"对齐"材料/工具 Agent 的输出

- [ ] 落库：
  - [ ] `cards.steps_json` ← JSON 数组
  - [ ] 不生成 `card_entities` 行（步骤作为容器，不是维度表对象）

- [ ] 置信度影响：
  - [ ] 若 `steps === null` 或 `[]` → `completeness` 扣 0.15（最严重的缺失）
  - [ ] 若步骤缺 `action` → 每条扣 0.05（由 scorer 遍历检查）

---

### 13.1.6 风险评估 Agent（`risk_agent.go`）

- [ ] 输出结构：包含两部分
  - [ ] `difficulty`：`{level, reason}`
    - [ ] `level` ∈ `{easy, medium, hard}`
    - [ ] `reason` ← 文字说明（如 "步骤 5 步以内，无高温/明火"）
  - [ ] `risks[]` 数组，每项：
    - [ ] `level` ∈ `{high, medium, low}`
    - [ ] `type` ← 风险类型，如 `cut` / `burn` / `electricity`...（与 Prompt 对齐）
    - [ ] `desc` ← 风险描述
    - [ ] `mitigation` ← 缓解建议

- [ ] **关键约束：仅读 `cleaned_text`，不读 `steps_json`**
  - [ ] 这样质检 Agent 需要额外检查 `risk_suspect`（见 12.2.2）

- [ ] 落库：
  - [ ] `cards.difficulty` ← `level` 值（枚举，供筛选）
  - [ ] `cards.difficulty_reason` ← `reason` 值（供显示与复核比对）
  - [ ] `cards.risk_json` ← 整个 `risks[]` 数组

- [ ] 置信度影响：
  - [ ] 若 `risks === null` 或 `[]` → 不直接扣 `completeness`（风险是可选的）
  - [ ] 但若步骤含高温/刀具等，而 `risks` 为空 → 标 `risk_suspect` flag，扣 `quality` 0.05

---

### 13.1.7 质检 Agent（`quality_agent.go`）

- [ ] 输入：原文 + 卡片 JSON
- [ ] 输出结构：**证据清单**（不是分数），包含：
  - [ ] `step_conflicts[]`：步骤时序冲突对，每项 `{step_a_seq, step_b_seq, reason}`
  - [ ] `grounding_issues[]`：实体与原文不一致的问题，每项 `{entity_name, issue_desc}`
  - [ ] `missing_fields[]`：卡片中缺失的必填字段

- [ ] **质检 Agent 不直接输出置信度分数，分数由代码计算**（见 12.2）

- [ ] 落库：证据清单暂不入库，由 scorer 读取后生成 `cards.confidence_detail` + `quality_flags`

- [ ] 若质检 Agent 失败：
  - [ ] 卡片仍生成，但 `confidence = null`, `confidence_detail = null`
  - [ ] `quality_flags = ["quality_agent_failed"]`
  - [ ] 强制 `review_status = "pending_review"`

---

## 13.2 质检与打分模块（`internal/quality/`）

### 13.2.1 Scorer 实现（`scorer.go`）

- [ ] 函数签名：
  ```go
  func ScoreConfidence(card *Card, qcEvidence *QCEvidence) *ConfidenceDetail
  ```

- [ ] 四维打分函数（见 12.2.2）：
  - [ ] `scoreCompleteness(card)` 返回 0-1
    - [ ] 基线 1.0，按缺失字段扣分（表 12.2.2）
  - [ ] `scoreTemporal(card, conflicts)` 返回 0-1
    - [ ] 基线 1.0，按冲突对数量扣分
  - [ ] `scoreGrounding(card)` 返回 0-1
    - [ ] 逐实体检查 evidence 是否在 raw_text 中命中（不需持久化 raw_text，从数据库读）
  - [ ] `scoreQuality(card, qcEvidence)` 返回 0-1
    - [ ] 按 `clean_degraded`, `risk_suspect`, 异常值等综合扣分

- [ ] 总分计算：
  ```go
  confidence = 0.30*completeness + 0.30*temporal + 0.20*grounding + 0.20*quality
  ```

- [ ] `GenerateQualityFlags()` 函数：
  - [ ] 返回字符串数组，每项是 6 种取值之一（见 5.2.2）：
    - [ ] `missing:{field}` 如 `missing:tools`, `missing:steps`
    - [ ] `conflict:{seq_a}-{seq_b}` 如 `conflict:2-4`
    - [ ] `ungrounded:{entity_name}` 如 `ungrounded:砂纸`
    - [ ] `low_confidence` 若总分 < 0.50
    - [ ] `risk_suspect` 若风险为空但步骤含高风险词
    - [ ] `clean_degraded` 若清洗过度或不可靠

- [ ] 单元测试：
  - [ ] 对各维度的打分逻辑编写单元测试（`_test.go`）
  - [ ] 验证加权公式的计算正确性
  - [ ] 边界测试（全缺、全有等场景）

---

### 13.2.2 缺失字段的处理

- [ ] 若某路 Agent 失败，卡片该字段为 `null`：
  - [ ] 置信度计算时，该维度按"该实体数 = 0"处理（不参与分母）
  - [ ] 示例代码：
    ```go
    if card.Materials == nil || len(card.Materials) == 0 {
        // 在 scoreGrounding 中
        validEntityCount -= expectedMaterialCount  // 分母减少
    }
    ```

## 13.3 异步任务模块（`internal/mq/`）

### 13.3.1 生产者（`producer.go`）

- [ ] 同一事务中：
  - [ ] 写 `agent_tasks` 表
  - [ ] 写 `agent_items` 行（初始状态 `pending`）
  - [ ] 写 `task_outbox` 行（状态 `pending`）
  - [ ] 三者一起 commit，一起 rollback

- [ ] 客户端幂等键：
  - [ ] 检查 `(user_id, idem_key)` 的唯一约束
  - [ ] 若重复提交 → 返回旧任务的 ID（秒回，不重复投递）

- [ ] Outbox 投递协程：
  - [ ] 定期扫 `task_outbox` 中 `status = "pending"` 的行
  - [ ] 投 RabbitMQ → 成功标 `sent`
  - [ ] 消费者 ACK → 标 `confirmed`
  - [ ] 扫描间隔与重投策略见 6.3

---

### 13.3.2 消费者（`consumer.go`）

- [ ] 启动消费循环：
  - [ ] 从 AMQP headers 恢复 `traceId`（跨链路追踪）
  - [ ] 创建 context with traceId

- [ ] 消费幂等性：
  - [ ] 检查 `agent_items` 的 `(task_id, tutorial_id, agent_name)` 唯一键
  - [ ] 若已处理 → 幂等返回成功（不再调用 Agent）
  - [ ] 若新任务 → 分布式锁 + 执行 + 解锁

- [ ] 错误处理：
  - [ ] 子任务失败 → 指数退避重试（见 6.3）
  - [ ] 超过重试限制 → 发送到 DLX

### 13.3.3 处理器（`handlers/agent_pipeline_handler.go`）

- [ ] 不反向 import producer（依赖由上层注入）

## 13.5 API 接口模块（`internal/controller/`）

### 13.5.1 卡片控制器（`card_controller.go`）

- [ ] `GET /cards/{id}` ← 详情接口
  - [ ] 权限检查（见 12.3.2）
  - [ ] 许可证检查（viewer 不能看 `research-only`）
  - [ ] 返回完整 Card 对象（包括四维分数、flags、removed_spans）

- [ ] `PUT /cards/{id}` ← 编辑接口
  - [ ] 仅 `draft` 状态允许编辑
  - [ ] 保存后自动重算置信度
  - [ ] 若置信度下降 → 强制 `pending_review`

- [ ] `PUT /cards/{id}/publish` ← 发布接口
  - [ ] editor 仅能发布自己集下且置信度 ≥ 0.80 的卡片
  - [ ] admin 可发布任何卡片
  - [ ] 发布后 `status = "published"`, `review_status = "reviewed"`

- [ ] `PUT /cards/{id}/archive` ← 下架接口
  - [ ] `published` 或 `draft` → `archived`
  - [ ] 记操作审计日志

- [ ] `PUT /cards/{id}/unarchive` ← 恢复接口（仅 admin）
  - [ ] `archived` → `published`

- [ ] `PUT /cards/{id}/review` ← 人工复核接口（admin/reviewer）
  - [ ] 接收修改建议与最终决策（approved/rejected）
  - [ ] 保存复核记录到 `review_logs`
  - [ ] 若 rejected → `status = "draft"`, 编辑可重新修改

### 13.5.2 任务控制器（`task_controller.go`）

- [ ] `GET /tasks/{id}` ← 查询任务进度

- [ ] `GET /tasks/{id}/cards` ← 查询任务生成的卡片
